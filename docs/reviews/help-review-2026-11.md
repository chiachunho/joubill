# Help 說明網站 review（2026-11）

範圍：`src/app/help/**` 的 14 頁，對照 `dev` 上 #166（bot 文案重整）之後的程式碼。每一處引用的 UI 字串都 grep 過，還在程式裡的就不列。這份報告只列出問題，沒有改程式。

等級：

- **P1**：寫錯了，使用者照著找會找不到，或會誤解

## 一、過時（寫的和現在的行為不一樣）

### P1

1. **機器人刪除後的訊息格式是舊的。**
   `troubleshooting/page.mdx:31` 寫「已刪除 ⟨金額⟩，原本由 X 記錄 — 操作者」，現在是劃掉的「🗑 ~~說明　金額~~」加上「X 記錄 · Y 刪除」（`src/lib/record-notice.ts:92`）。同一頁第 108 行和 `adding-expenses` 都已經是新格式，只剩這一句沒改。

2. **「多行分帳已經改用按鈕了」這句話機器人已經不說了。**
   `troubleshooting/page.mdx:77` 的標題引用的是舊訊息，現在的回覆是「一次記一筆就好，誰分、份數記完再用 ☰ 調整 改」（`src/lib/parseAdd.ts:397`）。使用者拿看到的訊息來搜尋，會找不到這一題。建議把標題改成現在的那句話，內文留著。

3. **匯率欄位怎麼標示來源，寫錯了。**
   `adding-expenses/page.mdx:148` 和 `multi-currency/page.mdx:55` 說欄位「下方」會標示來源是「市場匯率／群組自訂匯率／此筆自訂匯率」。實際上：
   - 來源寫在**空欄位的 placeholder 裡**：`0.22（當日市場匯率）` 或 `0.22（群組自訂匯率）`（`src/lib/rate-source-label.ts`、`ExpenseForm.tsx:744`）
   - 欄位下方顯示的是換算結果 `≈ 660.00 TWD`
   - 「此筆自訂匯率」這幾個字畫面上沒有出現過。自己填了數字之後，就不再標示來源

   建議改寫成「欄位空著時，灰字會顯示目前套用的匯率和來源（當日市場匯率或群組自訂匯率）；填入數字就改用你填的。下方會顯示換算後的金額。」`multi-currency` 優先序表格可以繼續用「此筆自訂匯率」當概念名稱。

### P2

4. **邀請碼不會過期，但三個地方寫「已過期」。**
   `invite-members/page.mdx:30`、`:95` 和「加入群組」段落都把「已過期」列為一種情況。`group_invites.expires_at` 有欄位，但建立邀請碼時從來不設（`src/lib/invites.ts:70`），所以碼只會被**重設**而失效。讀者會以為要定期重發。建議刪掉「已過期」，或改成「已被重設」。

5. **邀請碼字元的說法不精確。**
   `invite-members/page.mdx:71` 說「字元裡沒有容易看錯的 0／O、1／I／L」。實際上碼裡**有** 0 和 1，只是不用 O、I、L，而且輸入時 O 會自動當 0、I／L 當 1（`src/lib/invite.ts:10`、`:34`）。建議改成「不會出現 O、I、L，打成這幾個字也會自動更正」。

6. **CSV「建立時間」只叫人加 8 小時。**
   `group-management/page.mdx:174` 寫「台灣時間請加 8 小時」，但現在每個群組有自己的時區。在 Asia/Tokyo 群組照做會錯 1 小時。另外 `src/lib/csv.ts:52` 的註解「The schema holds no group timezone」也已經過時。兩種改法：
   - 只改文案，寫成「建立時間是 UTC」，不要附加幾小時
   - 改程式，用群組時區輸出這欄（欄名一起改），讓 CSV 和群組設定一致

7. **網頁版頁面說兩邊「唯一的差別是返回的方式」，但差別不只這個。**
   `web-app/page.mdx:83`。只有網頁版能做的事：下載 CSV／.beancount、推播通知、加到主畫面、連結和合併登入方式、OAuth 授權頁。這幾件事其他頁面都有寫，只有這一頁說兩邊沒差。建議改成「畫面相同；以下只有網頁版有：…」。

8. **網頁版頁面列出的功能表是舊的。**
   - `web-app/page.mdx:81` 群組設定只列了「貨幣與匯率、成員管理、匯出、刪除群組」，漏了 **Telegram 群組**、**通知**、**動態紀錄**
   - `:91` 的「個人設定」只列了頭像、關於、登出，漏了 **登入方式**、**連結的應用程式**、**通知**／**主畫面捷徑**。這些在其他頁面都有用到，讀者在這裡卻看不到入口

9. **統計頁還留著改版說明。**
   `stats/page.mdx:53`（「不再固定統計全部歷史」）和 `:65` 的 FAQ「以前是全部歷史，現在數字變了？」是給改版當時的老使用者看的。新使用者不知道「以前」是什麼。建議刪掉這題 FAQ 和第 53 行的後半句。

### P3

10. `/join` 結果表格（`group-management/page.mdx:42`）漏了「• Bob 已經在了」（`join.ts:142`）。
11. 收據格式那一列（`troubleshooting/page.mdx:50`）只寫 JPG／PNG，實際上也收 WebP（`receipt-upload.ts:49`）。
12. 頁首標題是「加到主畫面」（`add-to-home-screen/page.mdx:1`），側欄卻是「加到主畫面與通知」。頁面有一半在講推播，建議標題跟側欄一致。
13. `group-management/page.mdx:60` 說要進「成員」區塊，但群組設定裡沒有叫「成員」的標題，成員直接列在「一起分帳 (n)」「暫停分帳 (n)」下面。

## 二、彼此矛盾或說不清楚

### P1

14. **「誰會被自動加入帳本」兩頁的清單不一樣，而且都漏了最常見的入口。**
    - `getting-started:24`：用過機器人、被拉進群組、`/join`
    - `group-management:3`：用過機器人、被拉進群組、`/add` 裡用提及選單點到的人（`/join` 放在下一節）
    - 兩頁都沒寫：**從群組裡的「開啟揪帳」按鈕打開 Mini App，就會自動加入**（`src/lib/auth/index.ts:107`）。這是讓朋友把自己加進來最省事的方法，現在只在 `/join` 段落順帶一句「想把自己加進來，點它就好」
    - 兩頁也都沒說：**用邀請連結加入 Telegram 群組的人，要機器人是群組管理員才會被登記**（`chat_member` 只送給管理員）。整個 Help 沒有一處建議把機器人設成管理員，但這是減少手動 `/join` 最有效的設定

    建議只在 `group-management` 保留一份完整清單（五個來源加上「設成管理員會更完整」），`getting-started` 改成兩三句話加連結。

### P2

15. **匯率「當天鎖定、永遠不變」的說法和自訂匯率互相矛盾。**
    - `multi-currency/page.mdx:97` FAQ：「每筆支出換算時鎖定的是當天的匯率，之後匯率再怎麼波動都不會影響已經算好的結果。」
    - `stats/page.mdx:59`：「每筆支出都用消費當天的歷史匯率」

    同一頁上方才講過：群組自訂匯率會套用到**所有**舊紀錄，改預設貨幣也會整本重算。所以「不會變」只對市場匯率成立。建議兩處都改成「市場匯率用消費當天的，所以不會因為今天的匯率變動；只有群組自訂匯率或改預設貨幣會重算」，或直接連到優先序表格。

16. **統計頁講隱私時連到「查看帳務」，但那頁沒講隱私。**
    `stats/page.mdx:15`「詳見[帳務](/help/balances)」。「所有成員都看得到、都能改」寫在 `adding-expenses` 的「修改或刪除」一節。建議改連到那裡。

17. **還款頁那條「只看還款」的提示做不到。**
    `settlement/page.mdx:54` 建議用「只看我的」和「總額／淨額」搭配來只看還款，但這兩個選項都不會篩出還款。建議刪掉；如果真的需要只看還款，應該在 App 加篩選，不是在 Help 裡教變通方法。

18. **「其他問題或回饋」沒有實際的聯絡方式，而且位置不對。**
    `troubleshooting/page.mdx:121` 寫「聯絡機器人的管理員」，但一般使用者不知道是誰。`<ContactEmail />` 已經有了（隱私權政策在用），可以直接放進來。另外這一節排在「網頁版收不到推播通知」**前面**，回饋這一節應該放在頁面最後。

19. **用詞沒有完全照 2026-11 UI 文案 review 的用詞表改。**
    那份表決定「A 把錢還給 B」叫**還款**，但 Help 還有：
    - `getting-started:8`「建議最少的**轉帳**次數」
    - `balances` `/settle` 段「**轉帳**次數最少」
    - `settlement:33` 欄位說明「付款人（誰**轉帳**）」

    表格欄名如果和表單一致可以保留，但說明文字建議統一改成還款。

## 四、結構

20. **「群組與成員」頁太長，也裝了不屬於它的東西。** 254 行裡有一半是 CSV 匯出和 Beancount 匯出，另外還有時區、通知主題、刪除群組。建議把匯出拆成獨立的「匯出」頁（CSV + Beancount），群組設定 → 匯出 的頁面也剛好對應過去。拆頁時要記得在 `layout.tsx` 的 `sections` 加一筆。
21. **「網頁建群組與邀請碼」頁也在講 Telegram 群組的邀請碼。** 這頁寫了「Telegram 建立的群組也能用邀請碼」，Telegram 連結那一段也和網頁群組無關。可以考慮改名成「邀請成員與網頁群組」，側欄的順序也挪到「群組與成員」後面。
